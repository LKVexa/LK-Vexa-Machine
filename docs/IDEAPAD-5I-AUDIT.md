# JA21 audit on Lenovo IdeaPad 5i — 14 October 2026

JA21 performs real software computations on the laptop's host processor. The audited component is a specialized JavaScript field-and-byte model, **not a physical JA21 silicon CPU, a general-purpose instruction-set CPU, or an ARM emulator**. Numerical correctness and repeatability passed. **Complete live-console validation and browser persistence remain unverified.**

Windows registry and a direct process CPUID probe agree on LENOVO model 83KS, family IdeaPad 5 2-in-1 16IAL10, and Intel Core Ultra 7 255U (GenuineIntel, family 6, model 181, stepping 0). The OS and processes report x64, Windows build 26200, and 14 logical processors available. Lenovo identifies this family as [IdeaPad 5i 2-in-1](https://psref.lenovo.com/Product/IdeaPad/IdeaPad_5_2_in_1_16IAL10). Intel lists the [255U as a 12-core, 14-thread processor](https://www.intel.com/content/www/us/en/products/sku/241860/intel-core-ultra-7-processor-255u-12m-cache-up-to-5-20-ghz/specifications.html). The 12-core count is a published specification, not a new local topology measurement. The CPUID hypervisor flag is set; this can also reflect Windows virtualization security and does not independently establish that this is a guest VM. These observations identify the execution host; they are not die inspection or manufacturing certification.

The backtest evaluates the original uploaded 2.2.0 truth tables as Boolean polynomials rather than indexing the current tables. This provides independent implementation of a regression oracle, **not an independent scientific specification of the arbitrary first map**. The selector threshold and analytic Fourier-mode checks use independent mathematical expectations. Raw-RAM tests substitute the sampling input boundary; the separate full-field datasets exercise production sampling unchanged. All 256 byte inputs were covered. The largest analytic propagation error was 2.03e-07, below the declared 1e-5 tolerance. No implementation mismatch was found in tested behavior.

The six table identities contain four distinct functions: lanes 1/3/6 are identical; lane 2 computes `(255 − 2 × byte) mod 256`; lane 4 returns 255; lane 5 returns 0. Selecting the largest absolute change therefore always gives 255 for inputs 0–127 and 0 for 128–255. Duplicate lanes 3 and 6 never win. Field writeback uses `(selected / 255) × 2π − π`: the two output bytes map to equivalent physical phases ±π. At lit sites (amplitude ≥1e-6), prior phase is replaced by approximately `(-amplitude, 0)` while magnitude is retained within floating rounding; darker sites are skipped. Tiny opposite imaginary roundoff signs may remain in stored samples; that is not a useful distinct physical phase. The raw byte-plane exports still distinguish 0 and 255. This is a limitation of the shipped operation; without an independent intended specification, the audit does not silently change its mathematics.

The byte benchmark processes 4,096 samples on a 64 × 64 grid: 4 KiB input, six 4 KiB lane outputs (24 KiB), and a 4 KiB selected result per scalar/batched path. The complex field separately occupies two Float32 planes (32 KiB). These sizes do not represent the total application memory requirement or silicon area. The modeled `cpuCycles = 4096 × 4` and `gpuWarps = 4096 / 32` are not measured hardware cycles or GPU activity. Both numerical paths execute CPU loops.
