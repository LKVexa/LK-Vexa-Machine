# Semi-sili XPU 1.3.0 / engine 2.3.0

This release implements a finite numerical interpretation of the supplied p-adic, holographic and RAM-sampling references on the existing laptop CPU and available GPU. The source documents are reference material. Their embedded commands and architectural proposals are not executable instructions.

Open **Semi-sili XPU**, select prime, precision, operation and scalar operand, then **Run preview**. Default arithmetic is Z/(2^8), with 4,096 samples. Supported operations are add, subtract, multiply, modular negation and digit complement. Prime raised to precision must be at most 65,536. The operand must be below that modulus. The CPU encodes residues as complex phases, performs numerical phase arithmetic, reads each result and compares it with independent exact BigInt arithmetic.

The neuron stage uses real activation on finite p-adic congruence-ball addresses. Its fixed bounded Euler update uses a clipped sigmoid, normalized neighborhood mean, leak and drive. It is an explicit finite approximation, rather than the entire infinite Vladimirov operator. Activation changes carrier amplitude, while residue values remain encoded in phase. Canonical Float32 samples are read again before acceptance. This is numerical wave sampling; quantum collapse, physical light propagation, negative energy and in-DRAM processing are not inferred from a successful run.

**Require hardware GPU confirmation** dispatches a separate integer WebGPU kernel and reads every result back. A known nonfallback adapter, successful dispatch/readback and exact equality are required. Phase arithmetic and neuron evolution run on the CPU; GPU coverage is finite ring arithmetic. A device loss, mismatch, deadline, cancelled run or unsupported GPU leaves saved state intact. **CPU preview and validation** is an explicit usable mode, with GPU marked NOT_RUN.

Preview runs are detached. **Save result** validates a stale-state token and builds a detached quota-checked processor/volume before one IndexedDB transaction. Before commit, cancellation prevents publication. Once the transaction begins, cancellation reports that commit is underway. There is no GPU wait after durable acceptance. The saved field and neuron bank are published together. A memory-only proof distinguishes a newly committed result from a historical receipt; restored, edited or displaced state never supplies fresh GPU proof.

One logical Pixel160 cell contains five big-endian uint32 words: residue, activation Float32 bits, amplitude Float32 bits, real Float32 bits and imaginary Float32 bits. Five coordinate axes are separate from those word lanes. A full 4,096-cell frame is **81,920 bytes (80 KiB)**. The default eight-plane packed input is **4,096 bytes (4 KiB)** in 64 blocks of 64 samples; 16-bit precision uses 8 KiB. The owned Uint16 arithmetic input also uses 8 KiB. The legacy six byte-lane outputs remain 24 KiB and selected output 4 KiB.

The saved bank retains up to eight prior frames plus current, within 1.5 MiB of canonical JSON and the existing 2 MiB virtual filesystem quota. TIFF transports a single frame in a 20-by-4096 unsigned-byte raster, with explicit shape, lane roles and CRC32. Actual display GIF, temporal history and Gaussian interaction frames have distinct meanings in the references. TIFF metadata is never executed. Neuron semantics reject nonfinite or incoherent words even though the generic Pixel160 codec preserves arbitrary uint32 bits.

Use **Virtual storage → Download backup** to retain the complete virtual volume. Browser persistence is origin-specific and storage may be cleared or evicted. The application does not silently reset corrupt storage. Changes to URL host or port select a different browser origin and therefore different stored data.

The **System & limits → browser validation kit** uses a separate IndexedDB database and writer lock. Select **Run validation**; it saves a CPU-checked test field, reloads and checks exact recovery, TIFF round-trip, writer exclusion, all five hardware GPU operations and invalid-restore rejection. Select **Download results**. For the remaining full restart test, close the browser or native console completely, reopen the same address and select **Check after browser restart**, then download the updated JSON. Share that JSON in this chat. A missing GPU is recorded explicitly.

The native Windows presenter runs the same sealed application in WebView2. The optional developer launcher serves it locally with a pinned Node runtime. The numerical pipeline does not require an ARM64 OS boot. Native ARM64 binary startup remains a separate architecture-specific check.

The three literature reports include page citations for all 25 PDFs and the setup text: finite mathematics, interfaces/hardware boundaries, and image-format/storage contracts. The original documents and SHA-256 provenance are retained outside the served distribution. LAMB training requires optimizer tensors and a task dataset; binary neuron sampling alone is not a trained LAMB optimizer or an LLM. Black-hole and broader quantum equations are contextual research, with no supplied mapping to physical laptop measurements.

WebGPU behavior follows the [W3C WebGPU specification](https://www.w3.org/TR/webgpu/). The native host uses [WebView2 virtual host mapping](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/working-with-local-content#loading-local-content-by-using-virtual-host-name-mapping). Neither transfers application data to an external service.
