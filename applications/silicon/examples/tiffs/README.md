# JA21 2.2.0 — regenerated TIFF samples

Generated by `node scripts/make-tiff-examples.mjs` from the included JavaScript HPU
(`pattern('vortex')`, then `bytes()`), except the explicit ordinal test image.
These are software-computed fixtures, not physical XPU measurements.

| File | Representation | Use |
|---|---|---|
| russl-field.tif | 128×128 Float64, classic little-endian | Importable sample-exact field atlas |
| russl-field-bigtiff.tif | Same samples, bounded BigTIFF | Importable alternate container |
| russl-field-big-endian.tif | Same samples, classic big-endian | Importable alternate container |
| ordinal-oracle.tif | 128×128 uint16, sample=k | Exact address test; NOT an importable field |
| phase.tif | 64×64 uint16 | Declared lossy phase visualization, no amplitude |
| processor-1.tif … processor-6.tif | 64×64 uint16 | Byte-lane samples scaled exactly by 257 |
| processor-7.tif | 64×64 uint16 | Route IDs scaled exactly by 257 |

All 16,384 atlas sites have meaning: real, imaginary, derived intensity and phase
of the original 4,096 complex working pixels. Raw scalar payload is 128 KiB;
container size additionally includes metadata. The three field containers have
different file hashes but equal sample/logical SHA-256 hashes in their receipts.

Start the console, open TIFF pixel lab and select Import field TIFF. Import only
stages a validated field. Apply is separate and resets transient HPU state; keep a
full-volume backup first. Ordinary TIFF/image viewers may not display floating
scientific images meaningfully. Use the lab for sample inspection or an appropriate
TIFF decoder. Phase/processor/oracle files are display/test exports, not full field
atlases and are intentionally rejected by the live-field import.

Receipts are hashes, not signatures. Check SHA256SUMS.txt to detect accidental
changes. This pack does not include a RUSSL language engine or Zarr store.
