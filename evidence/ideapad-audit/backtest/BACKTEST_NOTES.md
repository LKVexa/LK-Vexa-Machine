# JA21 independent backtests on the current laptop

Production source was read without modification. The runner used the pinned Windows x64 Node 24.21.0 and the integrated console's JA21 2.2.2 computation modules. Hardware identification and release-integrity verification are handled by the parent audit.

The JavaScript backtest passed 73 raw-RAM datasets and 40 complete complex-field datasets. It compared 2,777,088 output lane bytes and 462,848 route/selected bytes, plus 1,536 exhaustive lane comparisons and all 256 selector inputs. Full-field cases also checked 163,840 sampled bytes against independent scalar intensity arithmetic. Special cases included zero, maximum, threshold boundaries, repeated ascending and descending inputs, checkerboards, an impulse, tiny amplitudes, the four shipped patterns, and reproducible seeded data.

All 113 state round trips were byte-exact. Of 27 malformed inputs, 26 reached the loader and were rejected without changing any saved resident state; one excessive frame array was refused earlier by the state encoder. Forty field resets discarded derived byte lanes. Twelve subsequent execution comparisons reproduced the same logical data after timing counters were excluded explicitly.

All 256 OAM encodings round-tripped, and all 3,584 left/right shift cases matched ordinary integer multiply/divide, modulo, remainder and overflow rules. All 20 Boolean gate truth cases passed. Twenty-eight single spatial Fourier-mode cases matched analytic propagation with maximum absolute error 2.0336500727857754e-7. Twelve seeded forward/reverse propagations had maximum absolute reversal error 2.60770320892334e-7 and maximum relative energy error 7.401650701685788e-9.

Sixty-three TIFF exports were independently decoded with Pillow 12.3.0. Every one of their 258,048 pixels matched independently prepared expected samples, in addition to the JavaScript codec checks.

The first lookup map has no independent scientific specification in the inspected runtime. To avoid comparing the implementation only against itself, the oracle reads the original uploaded 2.2.0 truth tables and converts them into Boolean polynomials over GF(2). The runner evaluates monomials rather than reading current lookup tables. This establishes baseline regression equivalence, not scientific usefulness of that map. Lane 2 is also independently checked as `(255 - 2*b) mod 256`; lanes 4 and 5 are independently checked as constants 255 and 0. The six lanes contain four distinct maps.

The selector has a stronger mathematical result: because both extreme output bytes are available, the largest-change output is always 255 for inputs below 128 and 0 otherwise. All 256 possible inputs confirmed this independent threshold expression. Routes 1, 2, 4 and 5 appear 53, 1, 127 and 75 times respectively; duplicate routes 3 and 6 never win. Furthermore, phase writeback maps these selected bytes to +π and -π, which are the same complex phase. Every written pixel therefore becomes approximately `(-amplitude, 0)`. The full-field tests confirmed intensity preservation and this phase collapse. The byte-plane data still distinguishes 0 from 255.

No implementation mismatch was found in the tested behavior. These are software-model checks and do not establish physical JA21 silicon, a general instruction-set CPU, a hardware GPU, measured physical energy, or quantum computation. Raw-RAM cases temporarily replace the sample method at its input boundary; the separate full-field cases run the unmodified production sampling path. Real WebView2 startup and browser persistence are outside this runner and must keep their separate acceptance status.

An additional work-only native oracle project was prepared but was not executed. Its normal SDK build was blocked by protected global NuGet configuration. A supplementary direct compiler attempt remained pending and was interrupted. See `NATIVE_ORACLE_ATTEMPT.json`; use the parent audit's separately completed native-reference evidence rather than infer a PASS for this project.
